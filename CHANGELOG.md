# Changelog

All notable changes to this project are recorded here. Versions follow semantic versioning.

## Unreleased

### 0.3.0

Work that tests cannot verify: a project with no test tooling, a test that cannot run, and
checks only a person can do.

Added

- No-tooling mode: a single `None` row in the Verification commands table. Stages complete,
  and nothing is reported as verified by tests. No framework is chosen, installed or
  configured.
- `defer`, which records that an obligation's test is not being run, with a reason. Status
  `deferred`; evidence table `## Deferrals` (`DF-nn`), added on first use.
- `manual`, which records a person's result for a check in the new `### Manual verification`
  plan table (`MV-nnn`). Evidence table `## Manual results` (`MR-nn`), added on first use.
  Rules M1 and M2 check the table; gate rule G12; compliance rule C9.
- `status` lists what is not verified by tests, with a `Counts:` line. `compliance` gives
  notices, never findings, for open or failed manual checks and for deferrals.
- Behaviour items may name `MV-` ids in Verified by.
- Examples `examples/runs/no-tooling/` and `examples/runs/deferred/`, and story
  `examples/stories/09-new-project-no-framework.md`.

Changed

- A plan whose Verification commands table holds only `None` now passes. It was a finding.
- `defer` and `manual` add tables to the evidence document only when first used.

Upgrade: none needed. Features planned before this release are read as before.

### 0.2.0

The behaviour checklist: a document of observable behaviours, written at the plan stage,
checked, and tied to the evidence.

Added

- `tests/behaviour-checklist.md`, written by the plan stage from the extension's new
  `behaviour-checklist-template`. One section per acceptance scenario, quoting it word for
  word, then Other behaviours. Each item is a Given, When and Then in the specification's
  terms, naming the requirements it expresses and the obligations or exemptions that verify
  it. No new command: the plan stage writes it and asks for review, and nothing waits for
  approval.
- A `### Behaviour checklist` sub-heading in the Verification Plan. Its presence, or the
  presence of the file, switches the checklist rules on for a feature.
- Rules B1 to B7 in `plan` and `tasks`, and a `CHECKLIST` finding for a missing file; gate
  rules G10 (a behaviour item fixed at the baseline was changed or removed without an
  accepted record) and G11 (the checklist fails the plan checks once the baseline is
  recorded); compliance rule C8.
- Items are fixed at the first recorded run, in a new evidence table
  `## Behaviour items at baseline`. `expectation --item` records a change to or removal of an
  item, in `## Behaviour item changes`; `approve` accepts a `BX-nn` id.
- `status` prints a behaviour item table, the items not verified and an Item changes line,
  and `status --scenarios` prints each scenario's quote beside its items.
- The baseline is refused while the checklist fails, and a Red run is refused for an
  obligation that no item names.
- `examples/runs/frontend-planned/`, a screen feature that passes the plan check, and
  `examples/stories/08-behaviours-from-the-code.md`.

Changed

- The plan, tasks, analyze and implement stages carry the checklist: the plan stage writes
  and checks it, the tasks stage reports an untraced test task (B7), the analyze stage
  reports B1 to B7 and still modifies nothing, and the implement stage records item changes
  and reports the items not verified.
- The evidence document is `tests/tdd-evidence.md` for a feature that has none yet. A
  document at the top of the feature directory is read and written where it is. A feature
  with both is refused with exit 2, and nothing is written.
- The hook also refuses an edit that would remove `## Verification Plan` or
  `### Behaviour checklist` from a `plan.md` that holds one, and an edit to
  `tests/tdd-evidence.md`. The refusal for a task held by G10 or G11 names the way forward.
- `examples/runs/compliant/` was regenerated by a real run and holds the checklist and the
  evidence in `tests/`.
- Built and tested with Spec Kit 1.1.3.

Effect on features planned before this version

- A feature with no Verification Plan is reported as a gap by the tasks, analyze and
  implement stages, as before.
- A feature planned with 0.1.0 has no `### Behaviour checklist` sub-heading and no
  `tests/behaviour-checklist.md`. No checklist rule is applied to it, its evidence stays at
  the top of its directory, and each later stage reports the gap and names `/speckit-plan`.
  Running the plan stage again adds the sub-heading and the checklist, after which the
  rules apply.
- Output for such a feature is unchanged, except that a feature with no evidence yet gets
  its first document in `tests/`.
- `checklists/` is untouched, and Spec Kit's own scan of it does not see the behaviour
  checklist.

### 0.1.0

First release: the `integrated-tdd` extension and preset.

Added

- Preset `integrated-tdd`, wrapping the core `speckit.plan`, `speckit.tasks`,
  `speckit.analyze` and `speckit.implement` commands and appending a Verification Plan
  section to the plan template and label conventions to the tasks template. No command is
  added.
- Extension `integrated-tdd`, with the agent-neutral process rules, the evidence template,
  one standard-library-only check script (`tdd_check.py`, Python 3.9 or later) and a
  `pre_tool_use` event that refuses the edit marking a task complete while its gate fails.
- Check script subcommands: `plan`, `tasks`, `gate`, `status`, `compliance`, `run`,
  `classify`, `exception`, `expectation`, `decision`, `approve` and `hook`.
- Gate rules G1 to G9 and compliance rules C1 to C7.
- `tdd-evidence.md`, one document per feature, written only by the script, with a chained
  check value on each record and a generated Summary.
- Seven example stories under `examples/stories/`, two example runs under `examples/runs/`
  and `docs/evaluation.md`.

Known limits are listed in the README. Notable: the hard stop covers Edit, Write and
MultiEdit and not shell edits; `gate --all`, `status` and `compliance` slow down well beyond
the stated scale of 200 tasks and 1,000 records; and full enforcement is on Claude Code only.

Spec Kit version: requires 0.15.0 or later, the first release with extension runtime
events. Run against 1.0.2.dev0.
